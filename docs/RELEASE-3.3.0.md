# LSRE 3.3.0 — хеши, энтропия, устойчивый Ghidra и локальный агент

**Дата:** 27.11.2026
**Тег:** v3.3.0

## Что нового

- **`lsre_hash`** — новый MCP-инструмент: потоковые sha256/md5/sha1 для файлов до 2 ГБ; каталог
  отклоняется с понятной ошибкой, сервер не падает.
- **Классификация задач** отдаёт `entropy` (энтропия Шеннона текста) и `confidence`. Пороги и гейты
  не снижались — добавлены только метрики.
- **Ghidra JSON**: `jesc` теперь экранирует все непечатаемые символы (C0/C1, одиночные суррогаты),
  а `sanitizeJsonRegion` чистит ответ перед `JSON.parse`. Исправлено падение
  «Bad control character in string literal» на реальных декомпиляциях.
- **Цикл на локальной модели**: `num_predict` 800 (без него модель генерировала «до конца» и
  упиралась в таймаут), таймауты 900/1200 с, `pickModel()` с фолбэком
  `inkling2-mini → gemma4-lsre` и ошибкой «модель недоступна, доступны: …».
- **`engine/smoke.mjs`** — 7 быстрых проверок (инструменты, doctor, триаж 95 МБ, хеш,
  каталог-как-файл, фабрика, цикл); флаг `--full` добавляет Ghidra и Frida.
- **Форматы**: gzip определяется по сигнатуре `1f 8b`, а не по расширению.
- Убран дублированный каталог `engine/formats/formats`.

## Проверено

- `node engine/test.mjs` — 32/32.
- `node engine/smoke.mjs` — всё зелёное; триаж 95 МБ ≈ 400 мс; `lsre_hash` 95 МБ ≈ 250–430 мс.
- MCP: 31 инструмент (полный набор).

## Установка

1. Распаковать архив рядом с `engine/`, `model/`, `data3/`.
2. `lsre.exe` (Windows x64). Движку нужен Node 22+; Ghidra — JDK 21 + Ghidra 12.1.4
   (`GHIDRA_INSTALL_DIR`, `JAVA_HOME`); Frida 17 — по желанию.
3. Локальная модель: Ollama + `gemma4-lsre` (Gemma 4 12B, ~7,5 ГБ, комфортно на 12 ГБ VRAM).
