# LSRE v1.0.1 — критическое исправление путей

В v1.0.0 нашёлся баг: MCP-прокси искал движок REA по пути разработчика
(`D:\WORK\SMART BUILDER\rea-clean\...`). На этой машине путь существует, поэтому тесты
проходили; на любой другой LSRE запускался, но сервер анализа не поднимался.

## Исправлено

| Проблема | Было | Стало |
|---|---|---|
| Путь к REA | жёстко прописан путь разработчика | прокси ищет движок рядом с собой; стаб передаёт `REA_ENTRY` явно |
| Пути Ghidra/JDK по умолчанию | прописаны пути этой машины | берутся только из окружения (`GHIDRA_INSTALL_DIR`, `JAVA_HOME`) |
| Гонка при распаковке | два агента распаковывали одновременно | атомарный lock-каталог `.extract.lock` и ожидание готовности |
| Метаданные exe | `ProductName: Node.js` | `ProductName: LSRE`, `FileVersion: 1.0.1.0` |
| `PUBLISH.ps1` | локальный путь к exe по умолчанию | путь передаётся через `-ExePath` |

## Проверка после установки

```powershell
.\LSRE.exe --version          # 6.7.0
(Get-Item .\LSRE.exe).VersionInfo | fl ProductName, FileVersion
.\LSRE.exe doctor --json      # Ghidra находится, если задан GHIDRA_INSTALL_DIR
```

Первый запуск распаковывает окружение (~500 МБ). Если два клиента стартуют одновременно,
второй дождётся первого вместо порчи файлов.

## Известные ограничения

- Нет нативной сборки под Windows on ARM (x64 идёт через эмуляцию).
- Exe не подписан.
- Поиск в памяти лексический (FTS5), без эмбеддингов.
