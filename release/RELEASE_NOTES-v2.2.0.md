# LSRE 2.2.0 — один проход и память вместо повторного чтения

**Дата:** 28.10.2026
**Файл:** `LSRE.exe` — 273,0 МБ (было 334,6 в 2.1.2)
**SHA-256:** `B0864EF68278B5123AA0C8B273767BF283230DBD0773565ED23D26EA0AA345D8`

## Главное

- **`lsre_analyze`** — один вызов вместо цепочки: триаж PE → YARA-X → Kaitai по сигнатуре →
  факты и связи в память. Возвращает **факт-шит ≤2 КБ**. Дальше работа идёт по памяти,
  файл повторно не читается.
- **`lsre_context(query, budget_bytes)`** — готовая сборка контекста из памяти
  (FTS5 + вектор + RRF) под лимит байт. Модель больше не ищет факты сама.
- **Диета:** убраны бинарники Linux, macOS и ARM64. Windows x64 полностью сохранён:
  Ghidra headless, Frida, YARA-X, Kaitai, REA-инструменты, адаптеры Cutter/IDA/JEB.

## Проверено

24 критических теста через MCP: **24/24**.
Добавлены: факт-шит (`length=665 байт`), сборка контекста (`447 байт` при бюджете 500).

Прежние проверки на месте: path traversal, SQL-инъекция, вырезание секретов,
текст 200 000 символов, битые правила YARA, каталог вместо файла, триаж мусора и пустого файла.

## Экономия токенов

| Было (2.1.2) | Стало (2.2.0) |
|---|---|
| 5–8 вызовов × 3–6 КБ = 15–30 КБ | 1 вызов ≤2 КБ + контекст по запросу |

Оценка: **−70…−85 %** на типовом разборе. Работает и без LLM: триаж, YARA, Kaitai, граф
и память выполняются ядром.

## Совместимость

- 2.1.2 остаётся доступной отдельным релизом (для тех, кому нужен ARM64-Windows).
- Обновление с 2.1.x: распаковка в новый каталог, память в `LSRE_MEMORY_DIR` сохраняется,
  схема v4 совместима.
