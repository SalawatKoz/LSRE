# LSRE — Light Start Reverse Engineering

**Один exe. Реверс-инжиниринг бинарников через MCP — с памятью, которая не даёт потерять нить
между сессиями.**

LSRE — это автономная сборка вокруг [REA](https://github.com/morluto/rea): Ghidra, Frida и
локальная память в одном исполняемом файле для Windows. Ни `npm`, ни Python, ни установки —
скачали, запустили, подключили к любому ИИ-агенту по протоколу MCP.

```
[agent] ⇄ MCP ⇄ LSRE.exe ⇄ REA ⇄ Ghidra / Frida
                     ⇄ SQLite: факты, граф, якоря, страницы
```

## Зачем

Большие программы (CAD, BIM, инженерные пакеты) состоят из сотен бинарников. Агент проходит
их слоями: карта модулей → процессы и IPC → горячие точки. Каждая новая сессия обычно
начинается с нуля: контекст кончился, журнал перечитывать дорого, решения забыты.

LSRE решает именно это: **память хранит выводы анализа, а не историю чата.**

- 225 МБ exe, внутри Node 26, REA 6.7.0 (MIT), Frida 17.
- Схемы инструментов урезаны: **70 КБ вместо 3 МБ** в каждом запросе модели.
- Ноль сетевых обращений при старте.
- Память переживает перезапуск процесса: якорь сессии — **247 байт**, а не 30 тысяч.

## Быстрый старт

1. Скачайте `LSRE.exe` из [Releases](../../releases) (в репозитории exe нет — GitHub не
   принимает файлы больше 100 МБ).
2. Проверьте хеш (см. ниже).
3. Подключите к агенту:

```json
{
  "mcpServers": {
    "lsre": { "command": "D:\\путь\\LSRE.exe", "args": [] }
  }
}
```

CLI-режим:

```powershell
.\LSRE.exe --version
.\LSRE.exe doctor --json
```

Первый запуск распаковывает окружение (~500 МБ) в `%LOCALAPPDATA%\LSRE\6.7.0-lsre1`,
занимает 20–60 секунд. Дальше — мгновенно.

## Память между сессиями

| Инструмент | Назначение |
|---|---|
| `lsre_memory_remember` | сохранить факт, путь, хеш, решение (дедуп, вырезание секретов) |
| `lsre_memory_recall` | полнотекстовый поиск (SQLite FTS5 + bm25) |
| `lsre_graph_add` / `lsre_graph_query` | карта модулей: `calls`, `contains`, `duplicates`, … |
| `lsre_session_checkpoint` / `lsre_session_resume` | якорь «цель → сделано → следующий шаг» |
| `lsre_page_set` / `lsre_page_get` | страницы знаний: архитектура, соглашения |

Всё локально, в `%LOCALAPPDATA%\LSRE\memory\lsre.db`. Без сети, без ключей, без второго LLM.

## Триаж файла (`lsre_file_triage`)

Разбор PE без внешних зависимостей: секции с энтропией, импорты и DLL, overlay, TLS, .NET,
время сборки, подозрение на упаковщик — с уверенностью и списком улик. Адреса в двух системах
(`file_offset` и `rva`) плюс имя секции. Готовый блок `graph` (бинарник → зависимости) можно
сразу передать в `lsre_graph_add`. Советов модели не выдаёт — только факты.

## Визуал связей (`LSRE.exe ui`)

```powershell
.\LSRE.exe ui                 # http://127.0.0.1:7788
.\LSRE.exe ui --port 8080 --bank revit --open
```

Локальная страница читает ту же базу, что и агент, и обновляется вживую:

- узлы по типам (binary / module / function / service), связи по видам;
- раскладки: «иерархия зависимостей», кластеры, кольцо, сетка;
- узлы перетаскиваются — позиции сохраняются в базе;
- клик по связи удаляет её, два узла с Shift + «Связать» добавляют новую (пометка `user`);
- поиск по именам, фильтры по типам связей.

Интернет не нужен: граф-движок встроен в exe. Данные видны только локально (127.0.0.1).

Ограничения: комфортно до ~300 узлов; граф наполняется тем, что записал агент —
автоматического обхода ещё нет.

## Требования

- Windows 10/11 x64.
- Для глубокого анализа: **Ghidra 12.1.4** и **JDK 21** отдельно (в exe не входят — они
  весят ~700 МБ). Пути задаются через `GHIDRA_INSTALL_DIR` и `JAVA_HOME`.
- Frida уже внутри.

## Ограничения — честно

- Exe **не подписан**: SmartScreen покажет «неизвестный издатель».
- IDA/JEB/Cutter/Kuna не входят: инструменты объявлены и вернут «движок недоступен», пока
  вы не подключите их сами.
- Параллельный запуск двух агентов не защищён от гонки за каталог распаковки.
- Память без эмбеддингов: поиск лексический (FTS5), перефразирование находит хуже, чем
  векторный поиск.
- Анализ сотен тысяч бинарников — это месяцы работы CPU, а не «одно озарение».
