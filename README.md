# LSRE — локальный разбор программ и файлов

**LSRE** — настольный инструмент для глубокого разбора бинарей, документов и проектов: триаж по
сигнатуре, доказательства, локальная память с эмбеддингами и графом связей, Ghidra, Frida, YARA-X,
Kaitai — всё на своём компьютере, без облака и без отправки файлов наружу.

Оболочка — форк открытого интерфейса [Craft Anything](https://github.com/storytold/craft-anything)
(MIT OR Apache-2.0; выбрана ветка MIT), переработанный и дополненный. Движок — собственный, `engine/`
в этом репозитории. Обе части открыты.

## Что умеет

| Область | Возможности |
|---|---|
| Триаж | PE/ELF/Mach-O/ZIP/APK/JAR/DEX/PDF: секции, импорты с именами, экспорты, PDB, подпись, Rich, TLS-callbacks, оверлей |
| Хеши | `lsre_hash`: потоковые sha256/md5/sha1, файлы до 2 ГБ, каталог честно отклоняется |
| Форматы | Kaitai: png, sqlite3, gzip (по сигнатуре), pcap; YAML → JSON без исполнения тегов |
| Правила | YARA-X со своими правилами (совпадения + смещения) |
| Дизассемблер | Ghidra headless: обзор, декомпиляция, строки, xrefs; кэш проектов |
| Динамика | Frida 17: процессы, модули, запуск скрипта в цели |
| Память | SQLite FTS5 + эмбеддинги e5-small (384d): гибридный recall, контекст под бюджет байт, граф, страницы, наблюдения |
| Фабрика | Очередь задач со стадиями `triage → plan → apply → verify`, дедуп (Жаккар + косинус), гейт: `done` требует доказательств |
| Локальный агент | Полный цикл на своей модели (Ollama): план, правки через бэкап, проверка командой, откат и до 3 попыток с разбором ошибки |

## Требования

- Windows x64; для движка достаточно **Node 22+**.
- Для Ghidra: JDK 21 и Ghidra 12.1.4 (`GHIDRA_INSTALL_DIR`, `JAVA_HOME`).
- Frida 17 — по желанию, движок стартует и без неё.
- Локальная модель: Ollama + `gemma4-lsre` (Gemma 4 12B, ~7,5 ГБ; комфортно на 12 ГБ VRAM).

## Быстрый старт

```powershell
# движок как MCP-сервер (stdio JSON-RPC)
node engine\server.mjs

# смоук: 7 проверок; --full добавит Ghidra и Frida
node engine\smoke.mjs
node engine\smoke.mjs --full

# тесты движка
node engine\test.mjs        # 32/32
```

Приложение (`lsre.exe`) запускается рядом с `engine/`, `model/` и `data3/`; вкладки: Чат, Код,
Архитектура, Предпроект, Графика, **Фабрика**. Конфигурация — `data3/config.toml`.

## MCP

Движок отдаёт **31 инструмент** (см. [docs/MCP.md](docs/MCP.md)): триаж, память, граф, Ghidra,
Frida, фабрика задач и полный цикл на локальной модели. Подключение — стандартным MCP-клиентом,
без сети и ключей.

## Что нового в 3.3.0 (27.11.2026)

- **`lsre_hash`** — потоковые хеши sha256/md5/sha1, до 2 ГБ, с понятным отказом на каталоге.
- **Энтропия и уверенность** в классификации задач (`entropy`, `confidence`); пороги гейтов не снижены.
- **Ghidra JSON**: `jesc` экранирует все непечатаемые символы, `sanitizeJsonRegion` чистит ответ перед
  `JSON.parse` — исправлено падение «Bad control character» на реальных декомпиляциях.
- **Цикл на локальной модели**: `num_predict` 800, таймауты 900/1200 с, `pickModel()` с фолбэком
  (`inkling2-mini → gemma4-lsre`) и внятной ошибкой «модель недоступна, доступны: …».
- **`smoke.mjs`** — 7 проверок, включая каталог-как-файл и отсутствие модели; `--full` для Ghidra/Frida.
- Форматы: gzip определяется по сигнатуре, а не по расширению.
